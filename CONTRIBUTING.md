# Contributing

Contribute original explanations, clean measurements, independently written examples and reproducible findings. Keep documentation in English and make entry paths useful to someone without the original private implementation.

## Finding template

- Target/version and local artifact identity method.
- Question or failure trigger.
- Scope: provider/member, runtime and relevant source symbol or function address.
- Evidence: static, host-tested, build-validated, Xbox-observed, or pending.
- Procedure and expected result.
- Actual sanitized result.
- Limitations, remaining unknowns and next discriminating check.

Update the evidence map and machine-readable inventory when a finding changes. Label address interpretations and build-specific ABI assumptions. Never infer complete functionality from a resource filename or a parser pass.

## Publication boundary

Do not submit SDK headers/libraries, system executables, proprietary retail/modified UI resources, copyrighted artwork/audio, private client source dumps, raw UART/log files or private repository links. Do not include network endpoints, account/profile IDs, tokens, passwords or machine-specific paths. Use synthetic identifiers and original examples.

The license covers original contributions only. Resource names, addresses and factual observations do not transfer third-party asset rights.

## Local checks

Run all three Python examples in README. Check JSON syntax, relative Markdown links and inventory counts. For an integration finding, state the actual host/build/hardware checks performed; do not claim the public examples reran a private build.

Navigation acceptance must not automatically perform purchases, shutdown, formatting/deletion or persistent setting changes. Preserve recovery routes and backups.
