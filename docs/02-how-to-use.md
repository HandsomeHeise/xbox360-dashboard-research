# How to use this research

## Choose one experiment

Begin with a reversible destination such as the System landing page. Locate its provider/member in the inventory, identify the native controller and root/descendant IDs, and retain an Original recovery route.

This repository supplies no system resources, SDK, extraction utility or runnable dashboard. Supply those independently in your own lawful setup. Separate immutable inputs, editable XML, generated binaries and verification output.

## Establish the target

Record dashboard version and a local digest of the actual inspected artifact. The 17559 addresses are comparison points, not a compatibility detector. Check instruction bytes, function boundaries, calling convention and runtime module before using them.

Run the included Python examples to inspect the public inventory and understand the two small contract models. They need no console or SDK.

## Preserve the native contract

Read formats and converter pitfalls before editing. Preserve root class/ID, bindings, action paths, layout metadata and animation references. Start with one decorative surface or a narrowly scoped palette change.

The XML exporter is an editable view, not a complete representation of native DATA. Recover binary layout fields before rebuilding and calculate the compound allocation budget independently of the converter.

## Integrate a scoped replacement

Load private visuals in the correct runtime and prefix. Match provider plus member. Forward all native initialization arguments. After private creation, restore the native base path so relative child navigation still resolves correctly. Use absolute locators for private assets.

Create/attach before rendering. Fall back to native when creation, skin loading or base restoration fails. Preserve return page, focus, owner and profile when leaving custom Home.

## Validate in layers

First host-test session, profile, routing and message contracts. Then validate XUR8 bounds, allocation budgets, binary layout and archive member/hash readback. Finally test real hardware focus, child entry and B return.

Record route requested, native source selected, creation result, visible output and recovery after invalidation. A parsed resource is not visual acceptance. A System success is not universal settings acceptance.

Use the evidence map and contribution template to grow the handbook. A useful finding names its trigger, evidence level, scope, observed result and next unresolved check.
