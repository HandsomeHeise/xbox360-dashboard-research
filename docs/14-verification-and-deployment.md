# Verification, backups and deployment

This is an integration checklist, not a deployment script. Public examples never connect to hardware. Keep transport endpoints/credentials local.

## Host and build gates

Host-test session generation, stale actions, input edges, route phases, provider boundaries, item-text message fields, bookmarks and timeouts. Regressions should model the original failure: a virtual Twist source without child buttons, not a fixture that always supplies a Settings child.

The implementation checkpoint reports 150 passing host tests. Running this repository's examples does not rerun that private suite.

Validate XUR8 version/size, section bounds, independent DATA consumption, compound budget, native layout, root/class/binding/action contract and editable roundtrip properties. For palette-only edits, compare all bytes outside COLR.

Build the intended target configuration. Pack a new archive, reopen it, enumerate members and read back hashes. Verify dashboard and Guide archives when both change. Cache fingerprints must include edited input, original source and builder logic.

Earlier evidence reports 117 scene roundtrips, allocation/grid checks, archive readbacks and an Xbox Release build. These are build gates, not hardware acceptance.

## Backup and stage

Keep dated known-good copies of every replaced file and configuration, with local hashes and a compatible binary/archive set recorded. Retain Original access and a recovery method independent of the changed UI.

Stage new output, verify transferred bytes against local output, then activate the intended set. Successful transfer does not establish that the console loaded it. Avoid broad synchronization of unrelated system files.

## Hardware smoke test

1. Start with expected profile/controller and visible recovery.
2. Inspect loading, animated sign-in and Home transitions.
3. Enter one harmless submenu, move focus, open a child and B back.
4. Confirm original custom page/selection returns.
5. Exercise profile change, reconnect, title change and timeout recovery.
6. Inspect overscan, focus contrast, header/legend duplication and overlays.
7. Expand to other routes only after the first route is accepted.

Navigation checks stop before purchases, shutdown, storage deletion/formatting or persistent settings changes. Record exact deployed build and sanitized results. Acceptance of one build does not automatically certify a later cosmetic build.
