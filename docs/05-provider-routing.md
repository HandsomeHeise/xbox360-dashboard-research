# Provider routing and native base paths

A replacement has two identities: where its bytes come from, and which native provider owns its relative navigation.

## Match scope before member

RootScene.xur and similar names occur in different packages. Match absolute section scheme/provider/member, or a bare member against its supplied native base. Require provider-token boundaries: networkBackup is not provider network. Reject path-like strings masquerading as relative basenames.

Guide modules add exact application scope and dynamic scope checks. Resolve module scope again after unload/reload. Do not cache a module address indefinitely.

## Verify both scene signatures

The ordinary scene creation call associated with 0x921E77A8 and the lower hook at 0x921E7528 have different signatures in the studied implementation. The hook carries extra flags/arguments. Do not use a convenient SDK typedef without checking the actual ABI.

Forward base, source, init pointer, flags and extra arguments exactly. A visual substitution must not reinterpret native controller state.

## Restore native navigation

Create the private replacement, then send SET_BASE_PATH for its native provider. Preserve the original request's exact scope through the hash where available. Relative children must continue to resolve to native providers, where each can be independently substituted.

Make private images/audio absolute archive locators. Otherwise restoring native base can redirect custom asset lookup into a system package.

On failure, destroy only a valid owned partial scene and retry native creation. Do not return a half-created object. A successful HRESULT is also not a substitute for a usable object.

Test absolute request, bare member/correct base, wrong provider, substring collision, private file locator, missing hash, null input, and dynamic unload. Follow with actual parent-to-child navigation: a landing screenshot cannot prove relative resolution.
